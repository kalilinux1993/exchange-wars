## Phase 9r — CSS transform clobbered the SVG transform (2026-06-11, Jesse-reported)

78. **A CSS `transform` (even from a keyframe) fully replaces an element's SVG `transform` attribute — they don't compose.** Jesse's screenshot caught the monster rendered as a clipped blob in the scene's top-left corner instead of on the right. Cause: 9l positioned the monster with `transform="translate(160 52) scale(1)"` (an SVG attribute) AND animated it with a CSS `monster-bob` keyframe that sets `transform: translateY(...)`. CSS transforms win over the presentation attribute, so at every keyframe the positioning translate was discarded and the group fell to (0,0) — an ellipse centered at the origin shows only its lower-right quadrant = the corner blob. Fix: nest — OUTER `<g>` carries the positioning attribute, INNER `<g className="monster">` carries the CSS bob, so the bob composes within the placed frame. Lesson: never put a CSS transform/animation on the same SVG node as a positioning `transform` attribute; separate them across nested groups. The 9l combat-scene test asserted aria-label + splat but not POSITION — strengthened to assert the monster's parent group keeps its `translate(160` so this can't regress. Visual bugs need visual (or structural) assertions; a test that only checks "it rendered" misses "it rendered in the wrong place."

## Phase 9q — Quarantine the Corrupt Save (2026-06-11)

77. **"Recovers from a bad save" and "doesn't destroy a bad save" are different guarantees — we had the first, not the second.** loadGame already caught JSON.parse errors and started fresh, but (a) it skipped the shape gate importSaveString had, so a parseable-but-wrong object normalized into a half-baked Game that crashed later in render, and (b) on any failure the fresh game's first autosave silently OVERWROTE the unreadable original — permanent data loss with no trace. Fix: apply the same world+playerId shape gate, and on any failure QUARANTINE the raw save to `<key>-corrupt` before returning null, so a future-version/foreign/corrupt save is recoverable (export/import) instead of obliterated. The lesson is that graceful-degradation has two halves and tests should assert both: not just "starts fresh on garbage" but "the garbage is still there afterward." Pairs with the 9o boundary: boundary catches render crashes, this catches boot-time save failures — together the game can't be bricked by its own persisted state.

## Phase 9p — Combat Level & Titles (2026-06-11)

76. **Identity from data you already keep: a combat level and a worn title cost almost nothing.** combatLevel(xp) is a pure derived number (floor((atk+def+hp)/3), 1→99) — the single stat every OSRS player checks, and it required zero new state. Worn titles are just the earned-deed names offered in a `<select>` (chosen title in localStorage 'ew-title', guarded to only stick while still earned). Both render on the character panel header. A NOT-redeploy decision worth recording: adding combatLevel to quest.ts touches no command shape and draws no RNG, so verifySprint replays are byte-identical — the "redeploy verify-score on engine change" law is specifically about REPLAY-AFFECTING changes, and a pure display helper isn't one. Off-by-one caught by the test (1+floor(3/3)=2 at fresh, not 1) — the engine test asserting the fresh/maxed endpoints earned its keep. Progression feel (a rising number + a chosen identity) is disproportionately satisfying relative to its ~40-line cost, because the deeds/xp that feed it were already there.

## Phase 9o — The Lifeboat (2026-06-11)

75. **A determinism-pure engine makes crash recovery trivially safe.** Until now a single render throw white-screened the whole live game — and the risk is real and growing: monsterById throws on an unknown id, so a long-lived save crossing a future catalog change could brick the UI. An app-level React error boundary catches render/lifecycle throws, shows a recovery card (reload + copy-save-to-clipboard lifeboat), and — the key property — needs to do NOTHING to protect progress, because the world only mutates through saved commands and the autosave on disk is already the source of truth. The boundary just reads the save string; it never touches the world. Honest scope note: error boundaries catch render-path crashes only, NOT throws inside event handlers (applyCommand in an onClick) — but the render path (CombatScene/RegionMap/monsterById-during-render) was the white-screen risk, and a handler throw leaves the UI standing. Robustness here was cheap precisely because the architecture already separated "what's true" (the saved command log) from "what's drawn."

## Phase 9n — First Real Icons (original) (2026-06-11)

74. **The fetch tool decided the sourcing strategy: WebFetch markdown-converts, which annihilates SVG path data.** Route 2 (auto-pull game-icons.net CC BY files) was dead the moment I read WebFetch's own description — it returns markdown, and an SVG's `d="..."` has no markdown representation, so I'd get nothing usable and committing guessed paths = garbage shapes. So I authored ORIGINAL skill icons (sword/shield/heart, hand-written SVG I can reason about correctness of) as the default set: license-trivial (project's own art, logged under "Original project art" in CREDITS), a real visible upgrade over emoji, and — crucially — same-filename droppable, so a future game-icons/CC0 file overrides mine with zero code change. The glob pipeline (9m) picked them up in BOTH the browser build (Vite hashes + copies them, 342ms) and vitest (the glob now returns 3 urls, so the skills strip renders `<img>`; the fallback test moved to a deliberately-missing name). Honest-tooling lesson: check what a tool actually returns before architecting around it — and when you can't source the ideal asset, ship a clean replaceable default rather than block or fake.

## Phase 9m — The Art Pipeline (2026-06-11, Jesse-directed)

73. **"Rip free art" on an open-source public deploy is a LICENSING decision, not a fetch.** Jesse wanted real art; the honest correction was that Jagex/OSRS sprites are copyright and the OSRS Wiki's CC BY-NC-SA is non-commercial+share-alike — both unusable on a public open-source live site — while game-icons.net (CC BY) and CC0 packs (Kenney/OpenGameArt) are fine. He picked both. Since I can't verify binary art or transcribe SVG path data reliably headless (fabricating path strings = garbage shapes), the right brick was the PIPELINE, not pretend-art: an `Icon` component using Vite `import.meta.glob` to auto-discover `src/assets/icons/<name>.svg` with an emoji fallback — drop a file, rebuild, it appears; no manifest, no 404s (only existing files enter the glob), and jsdom sees an empty map so every test stays green on the fallback. Plus the bookkeeping an open-source project legally needs: CREDITS.md (CC BY attribution scaffold + the explicit NOT-USED list), the assets-folder README (naming + license rules), README credits section. Populating real icons is now a 2-minute drop-file step. Principle: when the human says "just grab art," the responsible move is to make grabbing art *safe and trivial* — build the slot and the license ledger first.

## Phase 9l — Combat, Animated (2026-06-11)

72. **Animation over a deterministic engine = render-time delta detection, never engine timers.** The combat scene (your figure vs a generated monster, hp bars, floating hit-splats) animates purely from React render diffs: a ref holds last round's hp + the log length as a gate, so a NEW log entry computes the damage delta and the splat text once, and the splat `<text>` is keyed by log length so it remounts and replays the CSS float-and-fade exactly once per round (FINDINGS #36's key-as-animation, third use). The engine stays clock-free — it never knows the UI animates. Monsters are generated deterministically (hue from id char-codes; dragonfire→horns, leech→tendrils, elite→crown+scale), so no art assets and same-beast-same-look. SVG transforms on `<text>` need no transform-box fuss for a small translate. The data was all already there (monsterHp/playerHp/log) — the brick was 100% presentation, which is the whole point of an engine that books everything.

## Phase 9j — Expedition Loadouts (2026-06-11)

70. **Convenience state belongs in localStorage, NOT the world.** Saved packs (up to 4, refill clamped to current inventory) are a cross-run UI preference that must never enter WorldState — putting them in the save would mean replaying them, snapshotting them, hashing them, and breaking determinism for a quality-of-life nicety. localStorage is the right home (same call the active-room and handle prefs already use), wrapped in try/catch because private-mode quota failure must never break embarking.
